1. 任务一：服务器端高阶并发与鉴权
1-1 [√] 服务器新增功能：使用线程池（自己拓展）
实现思路：不是调库，从 pthread_create 到条件变量调度全部手写。核心数据结构 threadpool_t 包含 pthread_mutex_t lock(互斥锁)、pthread_cond_t cond(条件变量)、pthread_t *threads(5个线程ID)、task_t *task_list(FIFO单向任务链表)、int thread_count(5)、int waiting_tasks(等待任务计数)、bool shutdown(销毁标志)。threadpool_init()：malloc 分配 pool → 初始化锁和条件变量 → 分配线程ID数组 → 批量 pthread_create 创建5个工作线程。thread_routine()：工作线程的无限循环体。加锁 → while(task_list==NULL && !shutdown) 调 pthread_cond_wait 阻塞等待 → 被唤醒后检查 shutdown && task_list==NULL 则退出 → 从链表头取任务(FIFO) → waiting_tasks-- → 解锁 → 执行 task->function(task->arg) → free(task) → 回到循环开头继续等待。threadpool_add_task()：创建 task 节点 → 加锁 → 尾插法入队(FIFO公平性) → waiting_tasks++ → pthread_cond_signal 唤醒一个工作线程 → 解锁。threadpool_destroy()：加锁 → shutdown=true → pthread_cond_broadcast 广播唤醒所有线程 → 解锁 → pthread_join 等待所有线程退出 → 遍历清理残留任务链表(防止内存泄漏) → free(threads) → pthread_mutex_destroy → pthread_cond_destroy → free(pool)。主线程 main() 中 pool = threadpool_init(5) 创建线程池，server_run() 中 accept 后 threadpool_add_task(pool, client_service, p_fd) 投递任务。
threadpool_t 结构体: dir_file_list/server/threadpool.h

  - 5个线程, 锁+条件变量初始化
thread_routine(): dir_file_list/server/threadpool.c
  - pthread_cond_wait 阻塞 → 取任务 → 执行 → free(task)
threadpool_add_task(): dir_file_list/server/threadpool.c
  - 尾插法 FIFO, pthread_cond_signal 唤醒
threadpool_destroy(): dir_file_list/server/threadpool.c

一、需求分析
当前 FluxCloud 的文件列表只能按文件名精确匹配，用户体验有限。增加 AI 自然语言搜索功能：用户在客户端输入一句话（如"找上周修改的那张风景照"或"列出所有图片文件"），服务端将自然语言转为搜索条件，返回匹配结果。
关键设计原则：完全复用现有代码架构，不引入新的网络基础设施。新增代码量约 100 行。

天气模块（dir_file_list.c 第2540-2670行）已完整实现了 HTTP 请求的全链路：gethostbyname DNS 解析 → socket connect 80 端口 → 手动拼 HTTP GET → read 接收响应 → strstr 截 JSON 体 → cJSON_Parse 解析。AI 搜索功能跟天气模块的架构完全一样——只是换了一个 API 端点和 HTTP 方法（GET 变 POST）。

1. DNS解析        → gethostbyname(XZ_API_NAME)     dir_file_list.c 第2551行
2. Socket连接     → socket() + connect()            第2568-2578行

void handle_ai_search(int client_fd, packet_t *pkg) {
    // ① 获取用户输入
    char *user_query = pkg->fname;
    // ② 构造AI提示词JSON
    char json_body[1024];
    sprintf(json_body, "{...prompt告诉AI你是文件搜索助手...}");
    // ③ HTTP POST请求（复用天气模块）
    struct hostent *hl = gethostbyname("dashscope.aliyuncs.com");
    int tcp_fd = socket(AF_INET, SOCK_STREAM, 0);
    // connect + 设置超时...
    char request[2048];
    sprintf(request, "POST /compatible-mode/v1/chat/completions HTTP/1.1\r\n"
                     "Host: dashscope.aliyuncs.com\r\n"
                     "Authorization: Bearer %s\r\n"
                     "Content-Type: application/json\r\n"
                     "Content-Length: %d\r\n\r\n%s",
                     AI_API_KEY, strlen(json_body), json_body);
    write(tcp_fd, request, strlen(request));
    // ④ 接收+解析AI响应（复用天气模块cJSON解析）
    char *response = malloc(4096);
    // ... 循环 read ...
    char *json_start = strstr(response, "\r\n\r\n") + 4;
    cJSON *json = cJSON_Parse(json_start);
    // 提取: choices[0].message.content → 关键词数组
    // ⑤ 在云盘目录中匹配（复用handle_list）
    DIR *dp = opendir(CLOUD_ROOT);
    char result_buf[4096] = {0};
    while ((ptr = readdir(dp)) != NULL) {
        if (文件名包含关键词) {
            strcat(result_buf, ptr->d_name);
            strcat(result_buf, "\n");
        }
    }
    closedir(dp);
    // ⑥ 回复客户端
    packet_t resp; resp.opt=OPT_AI_SEARCH; resp.fsize=strlen(result_buf); resp.status=0;
    write(client_fd, &resp, sizeof(packet_t));
    write(client_fd, result_buf, resp.fsize);
    free(response);
}

3-1 解决海量数据下 QListWidget 嵌套 Widget 导致的严重性能衰退（卡顿、内存飙升）问题
实现思路：初版使用 QListWidget::setItemWidget() 为每个菜品创建独立 DishItemWidget。假设菜单100道菜，就有100+个QWidget对象在对象树中，在ARM Cortex-A53低配开发板上内存飙到几十MB，滑动时所有Widget同时参与重绘，CPU满载，帧率掉到个位数。根本原因是QListWidget+setItemWidget 会为每个条目创建完整的QWidget子树，嵌入式设备无法承受。

  - 100道菜 = 100+个QWidget对象

void ServerWindow::handleAiRecommend(QTcpSocket *sock, const QJsonObject &obj) {
    int people = obj["people"].toInt();
    QString pref = obj["preference"].toString();
    // ① 查询全量菜单（复用 sendMenuTo 的查询模式）
    QJsonArray fullMenu;
    QSqlQuery q;
    q.exec("SELECT id, name, price, description FROM menu WHERE stock>0");
    while (q.next()) { fullMenu.append({id, name, price, desc}); }
    // ② 构造提示词
    QString prompt = QString("你是餐厅推荐助手。%1人用餐，偏好：%2。菜单：%3。推荐3-5道菜，返回[{id,reason}]")
                     .arg(people).arg(pref).arg(QJsonDocument(fullMenu).toJson());
    // ③ 异步HTTP POST（复用 WeatherFetcher 模式）
    QNetworkAccessManager *nam = new QNetworkAccessManager(this);
    QNetworkRequest req(QUrl("https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions"));
    req.setRawHeader("Authorization", "Bearer " + aiApiKey);
    req.setRawHeader("Content-Type", "application/json");
    QJsonObject body; body["model"]="qwen-plus";
    body["messages"]=QJsonArray{{{"role","user"},{"content",prompt}}};
    QNetworkReply *reply = nam->post(req, QJsonDocument(body).toJson());
    // ④ 异步处理AI响应
    connect(reply, &QNetworkReply::finished, [=]() {
        reply->deleteLater(); nam->deleteLater();
        if (reply->error() != NoError) { sendMenuTo(sock); return; }  // 降级
        // 解析AI响应 + 匹配菜品ID + sendJson推荐结果
        QJsonDocument aiDoc = QJsonDocument::fromJson(reply->readAll());
        QString content = aiDoc["choices"][0]["message"]["content"].toString();
        QJsonArray recs = QJsonDocument::fromJson(content.toUtf8()).array();
        QJsonArray result;
        for (auto &v : recs) {
            int recId = v["id"].toInt();
            for (auto &dish : fullMenu) {
                if (dish["id"].toInt() == recId) {
                    QJsonObject item = dish.toObject();
                    item["reason"] = v["reason"].toString();
                    result.append(item); break;
                }
            }
        }
        QJsonObject resp; resp["type"]="ai_recommend"; resp["data"]=result;
        sendJson(sock, resp);
    });
}
